19: 
20: ## 1. The problem
21: 
22: Streaming an Omarchy desktop to an iPad already works. Sunshine sends the picture, Moonlight
23: on the iPad shows it, and Omarchy ships an installer for Sunshine. What does not exist is any
24: path through it for a person who has not done it before.
25: 
26: Today that person must: know the two pieces of software are called Sunshine and Moonlight,
27: know Moonlight is an App Store search away among several near-namesakes, run a shell command,
28: survive an installer that currently dies half-finished, work out that Sunshine needs a login
29: they must invent, find a web page on a port they have never heard of, click past a certificate
30: warning, type an IP address on a touch keyboard, type a PIN back on the desktop, and then
31: discover that the whole thing shows a black screen because the session locked.
32: 
33: There is a written runbook for this (`docs/original-runbook.md`). It is accurate and it is
34: 2,400 words. That is the evidence of the problem, not the solution to it.
35: 
36: **Beam replaces the runbook with a plugin.** Install it, click one dot, get a picture on an
37: iPad.
38: 
39: ## 2. Who it is for
40: 
41: 1. **The first-timer.** Has installed the plugin and knows nothing else. Must reach a working
42:    stream without reading anything longer than a sentence at a time. This user is the reason
43:    the project exists and wins every design argument.
44: 2. **The repeat user.** Has done this before, is setting up their third machine, and wants one
45:    screen with everything on it and a button that does the whole job.
46: 
47: ## 3. What it is not
48: 
49: - **Not a network tool.** Beam assumes the iPad can already reach this machine. It does not
50:   configure Wi-Fi, Tailscale, routers, VPNs or DNS, and it does not diagnose why they cannot
51:   see each other. If there is no address, it says so and stops.
52: - **Not a troubleshooter for arbitrary failure.** It detects and repairs a specific, known set
53:   of broken states (section 8). Anything else, it reports honestly and does not guess at.
54: - **Not host-aware.** Beam never asks or cares whether it is on a laptop, a desktop, a VM or a
55:   server with a monitor hanging off it. If there is an Omarchy session with a display and an
56:   address, Beam works. There must be no VM-specific, laptop-specific or GPU-specific code path
57:   anywhere in it.
58: - **Not a command-line tool.** No user-facing command, no `PATH` entry, no man page, no
59:   documented invocation. If a reviewer can reasonably describe the deliverable as "a script",
60:   it has been built wrong.
61: - **Not a credential holder.** It never creates, stores, transmits or reads back the Sunshine
62:   admin password, and it never handles a sudo password.
63: 
64: ## 4. Verified ground truth
65: 
66: These facts were established by running commands on host-example on 2026-09-19. Build against them.
67: 
68: **Plugin kinds.** The only valid values are `bar`, `bar-widget`, `menu`, `overlay`, `panel`,
69: `service`, and a declared kind must have its matching `entryPoints` key or the plugin is
70: refused (`/usr/bin/omarchy-plugin-validate`, lines 97 to 110). **verified**
71: 
72: **Do not use the `menu` kind.** It replaces the entire Omarchy menu rather than adding an item
73: to it. That is what Omalaunch does, declaring `"clonedFrom": "omarchy.menu"`. Beam must not
74: take over the user's menu. **verified**
75: 
76: **The stock Sunshine installer is broken.** `/usr/bin/omarchy-install-service-sunshine` runs
77: under `set -e` and calls `systemctl --user enable --now sunshine`. The current package
78: (`sunshine 2026.516.143833-4.1` in `extra`) ships its unit as
79: `app-dev.lizardbyte.app.Sunshine.service`. The old name does not exist, so the script exits
80: there, **before** opening the firewall, installing the admin web app, and adding the Hyprland
81: autostart line. Every user hits this today. **verified by reading the script and the package.**
82: 
83: **The installer's later steps can be reused, not reimplemented.** The script is a set of shell
84: functions followed by a linear body starting at the line `echo "Installing Sunshine..."`.
85: Sourcing everything above that line gives you `open_ufw_ports`, `install_admin_webapp` and
86: `enable_hyprland_autostart` to call directly. Beam must reuse these so that it opens exactly
87: the ports Omarchy opens and nothing wider. **verified**
88: 
89: **Sudo does not survive between SSH invocations without a TTY.** Priming sudo in one command
90: and relying on the cache in the next fails. Anything needing root must happen inside one root
91: call. **verified in the field, documented in the runbook.**
92: 
93: **A render node does not mean hardware encoding.** The runbook's step 2 says that finding
94: `/dev/dri/renderD128` means Sunshine will find VAAPI. On a Proxmox guest with `vga: virtio-gl`
95: that node is virtio-gpu (`1af4:1050`), which has no video encode engine at all, and Sunshine
96: falls back to `libx264`. **The only honest source is Sunshine's own log line `Found H.264
97: encoder: <name>`.** Never infer the encoder from the presence of a DRM device. **verified on
98: the `vm-example` guest.**
99: 
100: **`qrencode` 4.1.1-4 is in `extra`.** **verified**
101: 
102: **Moonlight on iPadOS is `id1000551566`, "Moonlight Game Streaming" by Diego Waxemberg.**
103: Confirmed against the iTunes lookup API. The canonical link is
104: `https://apps.apple.com/app/id1000551566`. Note that the store also lists "Steam Link" and
105: "VoidLink" for the same search terms, which is exactly why the user must not be told to
106: search. **verified**
107: 
108: **`pgrep -c` and `grep -c` print `0` and exit non-zero when the count is zero.** A
109: `count=$(pgrep -c x || echo 0)` idiom therefore yields the string `"0\n0"` and every later
110: arithmetic test on it fails. Capture first, then default. **verified: this bug was written and
111: then caught by running it.**
112: 
113: ## 5. Architecture
114: 
115: **What is being built is an Omarchy Quickshell plugin.** It lives in the bar. The entire user
116: experience is a dot in the bar and a panel that opens when you click it. There is no command
117: for a user to learn, nothing to type, and nothing in a terminal except the one install step
118: that needs a password and is deliberately shown to the human.
119: 
120: Inside the plugin there is a bash helper. **It is an internal implementation detail, not a
121: product surface.** It exists because QML is a poor place to shell out from repeatedly and
122: because a single source of facts keeps the bar dot and the panel honest. A user never sees it,
123: never runs it, and its name never appears in the interface. Do not design around it as though
124: it were the product, and do not add user-facing commands to it.
125: 
126: With that understood, one rule governs the split: **the helper owns every fact and every
127: action; the QML only asks and relays.** This is the pattern that made the Lamplight plugin
128: reliable. The bar dot and the panel can then never tell the user two different stories, and
129: the logic stays testable without a GUI.
130: 
131: ```
132: manifest.json        kinds: service, bar-widget, panel
133: BarWidget.qml        the product: one dot in the bar, always visible
134: BeamPanel.qml        the product: the wizard and the expert screen
135: Service.qml          holds state, polls the helper, queues actions
136: QrCode.qml           renders a QR png
137: bin/omarchy-beam     internal helper. Every fact, every action. Prints JSON.
138: ```
139: 
140: The helper ships **inside the plugin directory**, and the QML resolves its path relative to
141: itself. It is not installed to `~/bin`, not put on `PATH`, and not documented to users. A
142: hardcoded `/home/<someone>/bin/...` path works on exactly one machine, and this plugin is for
143: strangers.
144: 
145: ## 6. The internal helper contract
146: 
147: `bin/omarchy-beam <command>`, called only by the QML. This section is normative because the
148: QML depends on every key, not because any of it is a user interface. Nothing here is
149: advertised, documented to users, or reachable except through the panel.
150: 
151: | Command | Does |
152: |---|---|
153: | `status` | prints the JSON below, always exit 0 |
154: | `doctor` | the same facts, human readable, with what to do about each failure |
155: | `install` | runs Omarchy's installer, then `repair` to finish what it skipped |
156: | `repair` | fixes any of the known broken states in section 8 |
157: | `ports` | reopens the firewall ports using the stock installer's own function |
158: | `admin` | opens the Sunshine admin page |
159: | `pin` | opens the admin page's PIN tab |
160: | `qr <text>` | writes a QR png, prints its path, caches by content |
161: | `hold on\|off\|auto` | holds the session awake, or gives idling back |
162: | `greet` | fires the one first-run notification, once ever |
163: | `address` | prints the address to type into Moonlight |
164: | `undo` | removes Sunshine and everything the plugin added |
165: 
166: ### `status` JSON
167: 
168: ```json
169: {
170:   "installed": false, "version": "", "running": false, "processes": 0,
171:   "unit": "", "unitEnabled": false,
172:   "ufwRules": 0, "ufwPresent": true, "autostart": false,
173:   "adminUp": false, "adminConfigured": false, "adminUrl": "https://localhost:47990",
174:   "displayFound": false,
175:   "encoder": "", "encoderKind": "unknown",
176:   "recommendedRes": "1920x1080 · 60fps", "recommendedBitrate": 20,
177:   "pairedClients": 0, "streaming": false, "locked": false,
178:   "address": "100.64.0.10", "addressKind": "tailscale", "lanAddress": "192.0.2.10",
179:   "nextStep": 2, "ready": false
180: }
181: ```
182: 
183: Definitions that are not obvious:
184: 
185: - `encoderKind` is `hardware` if the encoder name contains vaapi, nvenc, qsv, amf or vt;
186:   `software` if an encoder was found and is none of those; `unknown` if Sunshine has not said
187:   yet. Derived from Sunshine's log only (section 4).
188: - `recommendedRes` and `recommendedBitrate` follow from `encoderKind`: hardware gets
189:   `2560x1600 · 60fps` at 40 Mbps, software gets `1920x1080 · 60fps` at 20 Mbps.
190: - `addressKind` is `tailscale` when the address starts `100.`, else `lan`, else `none`. Prefer
191:   a tailnet address: it keeps working when the iPad leaves the house.
192: - `streaming` is the last of `CLIENT CONNECTED` / `CLIENT DISCONNECTED` in the Sunshine log.
193: - `nextStep` is **the single definition of how far the user got**, so that the bar dot, the
194:   wizard and a notification can never disagree. It returns the lowest unfinished step:
195:   `2` if not installed, or ports/autostart/running incomplete; `4` if no admin login; `5` if
196:   nothing is paired; `6` when everything is done.
197: 
198: ### Hard rules on the helper
199: 
200: - **Never handle a sudo password.** Not on a command line, not in a variable, not on stdin.
201:   The one command that needs root (`install`) runs in a terminal the human can see and type
202:   into.
203: - **Never touch the Sunshine admin password.** Beam detects only that a `username` line exists
204:   in `sunshine.conf`. It never reads, sets or transmits the password.
205: - **`status` must be cheap.** It runs every two seconds while a stream is live. Tail the log,
206:   do not read it whole.
207: - **`status` must never fail.** Missing files, missing `ufw`, missing `tailscale`, Sunshine not
208:   installed: all are normal states with a JSON answer, not errors.
209: 
210: ### 6.4 Detection recipes
211: 
212: These are the exact mechanics. They were established by running them; do not substitute
213: something that looks equivalent without testing it.
214: 
215: **Installed / running / count.** `command -v sunshine`, `pgrep -x sunshine`, and for the count
216: `n=$(pgrep -cx sunshine 2>/dev/null); printf '%s' "${n:-0}"`. Capture first: see section 4 on
217: why `|| echo 0` is wrong here.
218: 
219: **Which unit the package ships.** Probe both `app-dev.lizardbyte.app.Sunshine.service` and
220: `sunshine.service` against `systemctl --user list-unit-files`; empty means the package provides
221: no user unit and the Hyprland autostart line is the only launcher.
222: 
223: **Firewall rules.** Count lines matching the comment `omarchy-sunshine` in
224: `sudo -n ufw status`. Use `-n`: a status check must never block on a password prompt. No `ufw`
225: at all is a valid state, not a failure.
226: 
227: **Autostart.** `grep -Fxq 'o.launch_on_start("sunshine")' ~/.config/hypr/autostart.lua`.
228: 
229: **Admin login exists.** A `username` line with a non-empty value in
230: `~/.config/sunshine/sunshine.conf`. Never read the password field.
231: 
232: **Paired clients.** Count objects carrying a `uniqueid` in
233: `~/.config/sunshine/sunshine_state.json`. Guard the result: if it is not all digits, it is 0.
234: 
235: **Encoder.** `grep -aoiE 'Found H\.?264 encoder: *[a-z0-9_]+' ~/.config/sunshine/sunshine.log |
236: tail -1`, then strip to the name. This is the only permitted source (section 4).
237: 
238: **Display captured.** `Found display` or `Found monitor` anywhere in the same log.
239: 
240: **Streaming now.** The last line matching `CLIENT (CONNECTED|DISCONNECTED)` in the log, and it
241: counts as streaming only if it is the CONNECTED one. Tail the log; this runs every two seconds.
242: 
243: **Address.** `tailscale ip -4 | head -1` if Tailscale is present, else the `src` field of
244: `ip -4 route get 1.1.1.1`. Prefer the tailnet address.
245: 
246: **Session locked.** `pgrep -x hyprlock`, or `hyprlock` present in `hyprctl -j clients`.
247: 
248: **Reusing the stock installer's functions.** Find the line number of the literal line
249: `echo "Installing Sunshine..."` in `/usr/bin/omarchy-install-service-sunshine`, write
250: everything above it to a temp file, append a call to the function you want
251: (`open_ufw_ports`, `install_admin_webapp`, `enable_hyprland_autostart`), and run it. The
252: firewall one needs root: run it as **one** root call, because the script's inner `sudo ufw`
253: lines then need no further authentication, and because sudo caching does not survive between
254: invocations without a TTY (section 4).

256: ## 7. The user experience
257: 
258: ### 7.1 Discovery: the part that actually matters
259: 
260: A person installs the plugin and is told nothing. Solving that is the product. Three things,
261: all required:
262: 
263: 1. **The bar dot is visible from the moment the plugin is enabled**, greyed, labelled `set up`.
264:    It is not hidden until configured. A widget that appears only once you have finished setting
265:    it up cannot help you set it up.
266: 2. **One notification, once, ever**, four seconds after first load, and only if nothing is set
267:    up: *"Beam is ready to set up — Click the Beam dot in your bar to stream this desktop to
268:    your iPad."* The marker lives in the helper's state dir so it cannot fire twice. Per house
269:    rules a notification must not steal focus, and clicking it must take you there.
270: 3. **The wizard opens on the first unfinished step**, not always at step 1. Someone who paired
271:    an iPad yesterday and opens Beam today lands on the last screen, not a tour.
272: 
273: ### 7.2 Guided mode: six steps, one thing each
274: 
275: The step rail across the top is clickable in both directions, with a tick on finished steps. A
276: wizard that will not let you go back and look at something is a wizard people fight with.
277: 
278: | # | Title | Shows | Done when |
279: |---|---|---|---|
280: | 1 | What you need | What Sunshine and Moonlight are, in three cards: an iPad, a few minutes, your password once in a terminal | user clicks Next |
281: | 2 | This computer | One button that opens a terminal and installs. Five live checks: installed, ports, autostart, running, screen captured. Then an encoder card quoting Sunshine's own log and the settings that follow from it | all five checks green |
282: | 3 | The iPad app | **A QR code to the App Store page.** The user points the camera. Names Diego Waxemberg so the right app is unmistakable | user clicks Next |
283: | 4 | Your login | A button that opens the admin page. Says plainly that the user invents this password, that Beam cannot see or recover it, and that the certificate warning is expected | `adminConfigured` |
284: | 5 | Connect | **A QR code of this machine's address**, plus the address in large monospace. Four numbered steps. A button to the PIN page. A line saying whether this address travels or stops at the front door | `pairedClients > 0` |
285: | 6 | Watch | Confirmation, plus three cards: the settings to use, that Moonlight sends Cmd as Super, and that Beam holds the session awake | — |
286: 
287: **The two QR codes are the single biggest usability win in the product.** They remove the two
288: worst moments: searching an app store full of near-namesakes, and typing an IP address on a
289: touch keyboard. QR codes must render on a **white background with a white quiet zone in every
290: theme.** A themed QR on a dark panel is one a phone camera silently refuses to read, and the
291: user has no way to find out why.
292: 
293: ### 7.3 Expert mode
294: 
295: One toggle in the header. Two dense columns, everything visible at once:
296: 
297: - **Left: state.** Twelve rows, each a dot plus key plus value: Sunshine, processes, firewall,
298:   autostart, unit, display, encoder, admin, paired, streaming, address, LAN.
299: - **Right: do it.** Six buttons (Install, Repair, Ports, Admin, PIN page, Remove), then a
300:   compact action report showing current progress, the result, and any actionable error in
301:   full. Remove asks first and names exactly what it destroys, including that paired iPads
302:   will need pairing again.
303: 
304: ### 7.4 Law 17: nothing scrolls
305: 
306: **User clarification, 2026-09-19: a plugin must never require scrolling to see its
307: information.** This applies to both modes and to every subsection, including action results.
308: There is no log-box exception. Do not put a `Flickable` or `ScrollView` around plugin content.
309: Guided mode keeps its explicit setup steps, each fitting completely on a fixed-height stage.
310: Expert mode shows every status row, control and action result together in grouped columns.
311: Width and a better arrangement are the remedies for overflow.
312: 
313: Use a concise action report instead of a scrolling terminal transcript. A bounded diagnostic
314: history may be retained separately for troubleshooting, but an error and its recovery action
315: must be readable in the panel without opening that history. Do not silently clip or elide
316: required information, hide overflow behind tabs, or shrink text until it is unreadable.
317: 
318: Verify at the real usable screen size and screenshot both modes, including long errors and
319: the Remove confirmation. Check every edge. Also verify at 1280x800 logical resolution so a
320: layout that fits the host's ultrawide monitor is not mistaken for a portable layout.
321: 
322: ### 7.5 Visual references from the running host
323: 
324: The live Lamplight, Burn Bar, Tesla, Detailed Weather and Chronos panels were inspected on
325: 2026-09-19. Their shared vocabulary is theme-derived colors, thin borders, modest rounded
326: corners, compact typography, grouped information and meaningful status animation. Lamplight
327: is the control-layout reference; Burn Bar and Tesla are the dense information references.
328: Follow the [host style notes](docs/style-reference.md). Screenshots establish the look on
329: this host, not small-screen acceptance for Beam.

331: ## 8. Known broken states Beam must own
332: 
333: This section is most of the engineering value. Each is a real state a user lands in.
334: 
335: | State | How to detect | What Beam does |
336: |---|---|---|
337: | Stock installer died half-way | installed, but ports/autostart/running incomplete | `repair` finishes the remaining steps using the installer's own functions |
338: | Two Sunshines on one display | `processes > 1`, or unit enabled **and** autostart line present | `repair` disables the packaged unit, leaving the autostart line as the single launcher |
339: | Session locks mid-stream, iPad goes black | `streaming && locked` | Hold the session awake **on the transition into streaming**, release on the transition out |
340: | Encoder assumed from a DRM node | n/a | Only ever read Sunshine's log, and show the user what it literally said |
341: | No address at all | `addressKind == "none"` | Say so on step 5 and stop. Do not attempt networking |
342: 
343: **The awake-hold is the highest-value single feature in this plugin.** A black screen is the
344: first row of every Sunshine troubleshooting table ever written, and it is not a Sunshine bug:
345: the compositor deliberately keeps lock surfaces out of screen capture. Holding the session
346: awake for exactly as long as an iPad is connected removes the entire class.
347: 
348: Implement it as an **edge trigger, not a level check.** Acting on the level would run two
349: processes a second for as long as someone watches a film. The hold must be released when
350: streaming stops, and the state marker must survive a shell restart so idling is never left
351: permanently disabled.
352: 
353: ## 9. QML gotchas that will cost a day each
354: 
355: Every one of these has already bitten this codebase or a sibling plugin. They are not
356: suggestions.
357: 
358: - **`WidgetButton` has no `contentItem`.** Children go in directly, and `hasVisualContent:
359:   true` is what tells it something is there despite an empty label.
360: - **Pointer handlers do not fire reliably inside these panels.** Use `MouseArea`.
361: - **`Rectangle.border.width` defaults to 1 even when never set.** Pin it to 0 or you get
362:   hairlines everywhere.
363: - **Never mutate a QML `var` array in place.** `pending.shift()` returns the item but leaves
364:   the property holding the original array, so a queue never empties and every action re-runs
365:   forever. Reassign with `slice()`.
366: - **Never name a panel file `Panel.qml`** — it collides with the shell's own type.
367: - **Panel content must nest inside `KeyboardPanel`**, with `PanelKeyCatcher` handling close.
368: - **A `Slider`'s `value:` binding is destroyed for good by the first drag.** If any slider is
369:   added later, use a `Binding` gated on `pressed`.
370: - **Bound diagnostic history.** Retain at most ~200 lines in memory. The panel presents a
371:   complete, concise action report, not a scrolling history. An unbounded string on a
372:   long-lived shell is a slow leak.
373: - **Do not blur a bar widget.** A blur repaints every frame. A scaled circle at low opacity
374:   costs nothing and looks the same at 18px.

376: ## 10. Acceptance criteria
377: 
378: Beam 1.0 ships when all of these pass **on a machine where Sunshine was never installed.**
379: 
380: 1. `omarchy-plugin-validate` passes.
381: 2. With Sunshine absent, `status` returns valid JSON with `nextStep: 2`, exit 0. Verify with
382:    `jq -e`.
383: 3. With Sunshine absent, `doctor` runs clean with no shell errors and no `arithmetic syntax
384:    error`.
385: 4. Enabling the plugin shows a grey dot labelled `set up`, and fires exactly one notification.
386:    Enabling it a second time fires none.
387: 5. Clicking the dot opens the wizard on step 2, not step 1.
388: 6. Step 2's button opens a visible terminal. The install completes **despite** the stock
389:    installer's unit bug, and all five checks go green without the user typing another command.
390: 7. After install, `processes` is exactly 1. Not 0, not 2.
391: 8. The encoder card quotes the string from Sunshine's log, and the recommendation matches it.
392: 9. Both QR codes render, and both are readable by a phone camera **in a dark theme and a light
393:    theme.**
394: 10. Completing step 4 flips `adminConfigured` without Beam ever seeing the password.
395: 11. Pairing an iPad flips the step 5 check and auto-advances the wizard to step 6.
396: 12. Starting a stream turns the bar dot to the accent colour and pulses it. Stopping returns it.
397: 13. With `holdAwake` on, starting a stream holds the session awake; stopping it gives idling
398:     back. Confirm with `omarchy toggle idle status` on both sides of the transition.
399: 14. All information and controls fit without scrolling, clipping or unreadable text in both
400:     modes, on the host and at 1280x800 logical resolution. Include long errors and the Remove
401:     confirmation. Screenshot both modes and inspect every edge; no log-box exception.
402: 15. `undo` leaves `pgrep sunshine` empty and zero `omarchy-sunshine` ufw rules.
403: 16. No `/home/example` or any other user-specific path appears anywhere in the plugin.
404:

5: 
6: ## What this is
7: 
8: **Beam** (`nixfred.beam`) is an Omarchy plugin that puts the desktop you are sitting at onto
9: an iPad, using Sunshine to send and Moonlight to show. A guided wizard takes a first-timer
10: from nothing to a live picture; an expert screen does the whole job in one click.
11: 
12: `PRD.md` is the spec and it is normative. **Astra6 (`gpt-6-astra`) builds from it, clean.**
13: `prototype/` holds a working first cut kept as reference: read it to see how something was
14: done, do not copy it wholesale. Where anything in this repo disagrees with the PRD, the PRD
15: wins.
16: 
17: ## The rule that shapes everything
18: 
19: **Beam does not know or care what kind of machine it is on.** Laptop, desktop, VM, a server
20: with a monitor hanging off it: if there is an Omarchy session with a display and an address,
21: Beam works. There must be no VM-specific, laptop-specific or GPU-specific code path anywhere
22: in it. This project began as a VM-specific runbook and was deliberately widened on
23: 2026-09-19; do not let host assumptions creep back in.
24: 
25: The second rule: **the CLI owns every fact and every action, the QML only asks and relays.**
26: The bar dot, the wizard and a terminal can then never tell the user three different stories,
27: and the whole product is testable without a GUI.
28: 
29: ## Two things Beam must never do
30: 
31: - **Never handle a sudo password.** The one step needing root opens a terminal the human can
32:   see and type into.
33: - **Never create, store or read the Sunshine admin password.** It detects only that a
34:   `username` line exists in `sunshine.conf`.

===== docs/style-reference.md =====
1: # Beam host style references
2: 
3: Inspected on 2026-09-19 through the running Omarchy shell's plugin registry, live panels,
4: local screenshots and installed QML. The active display was 5120x1440 at scale 1. These
5: observations establish a visual direction, not proof that every existing plugin fits every
6: screen. Screenshots remain outside the repository because they contain private host data.
7: 
8: ## User requirement
9: 
10: Plugins must never require scrolling to see their information. All information and controls
11: for the displayed plugin view must fit at readable sizes. No internal-scroller exception,
12: clipped bottom rows, hidden overflow tabs or required text reduced to ellipses. Beam retains
13: the deliberate guided setup steps from the PRD; each step must fit completely. Its expert
14: view shows all operational information together.
15: 
16: ## Panels inspected live
17: 
18: | Reference | Observed treatment | Apply to Beam |
19: | --- | --- | --- |
20: | Lamplight, `nixfred.lamplight`, 1.0.0 | Wide, shallow panel; live header; nine mode cards in three columns; full-width brightness and palette rows | Group related controls in visible rows; use horizontal space; put live status in the header |
21: | Burn Bar, `nixfred.burnbar`, 1.20.0 | Dense dashboard; prominent totals; colored metric cards; side-by-side charts, limits and local-compute readings; compact footer | Give current stream state a clear hierarchy and keep technical facts aligned and simultaneously visible |
22: | Tesla, `jankeesvw.tesla`, 1.5.0 | Four columns containing a visual summary, controls and compact labeled data sections; complete panel visible on this display | Arrange status, actions and connection details across columns; keep every operational field visible |
23: | Detailed Weather, `io.github.calebhat.weather`, 1.3.2 | Large current reading; horizontal forecast rows; compact two-column metric cards | Lead with the answer, then organize supporting details into clear groups |
24: | Chronos, `nixfred.chronos`, 1.0.0 | Day ring and month heading; compact calendar; progress rail and moon detail; restrained accent | Use a simple status motif and meaningful motion without consuming the space needed for information |
25: 
26: Weather's current live panel was a compact forecast grid. Its source also contains orbital
27: effects; do not claim those were active from this inspection. Lamplight's source comments
28: mention four columns, but the live layout and actual grid use three. Prefer observed behavior
29: over stale comments.
30: 
31: ## Shared visual direction
32: 
33: - Use the active shell theme's background, foreground, accent and font. The dark palette
34:   observed here is a reference, not a set of colors to hardcode. QR codes keep their white
35:   backing and quiet zone in every theme.
36: - Use thin outlines, modest corner radii, low-opacity selected fills and restrained dividers.
37: - Keep headings and labels compact. Align numbers, units and status values; use monospace
38:   for addresses and technical readouts. Reserve large type for the main state or next action.
39: - Put related facts in visible sections and columns, with actions near the state they affect.
40: - Animate state changes and useful live indicators. Existing QML provides references for
41:   reveals, count transitions and pulses; gate ongoing effects on visibility and relevance.
42: - Keep the plugin visibly part of the bar and shell, with consistent anchoring and Escape
43:   dismissal. Keep controls and the bottom edge visible, including during errors.
44: 
45: ## Beam layout direction
46: 
47: Keep a compact header with the Beam dot, current state and Guided/Expert switch. Guided mode
48: has its step rail, a stable stage and visible navigation. Expert mode groups all status,
49: connection details, actions and the complete current action report across the available
50: width. Do not copy the prototype's scrolling log box.
51: 
52: Test both modes with realistic long values, missing dependencies, action errors and the
53: Remove confirmation. Verify on the real host and at 1280x800 logical resolution before
54: claiming the no-scroll requirement is met. The existing prototype has not been changed or
55: visually verified by this style study.

2: #
3: # omarchy-beam - stream this Omarchy session to an iPad, and know whether it works.
4: #
5: # This is the whole brain of the Beam plugin. The QML panel and bar widget only
6: # ask this for JSON and relay button presses back, which is why the bar, the
7: # wizard and a terminal can never disagree about what is going on.
8: #
9: # It deliberately does NOT know or care what kind of machine it runs on. A
10: # laptop, a desktop and a VM are the same thing to it: an Omarchy session with a
11: # display, an address, and an iPad somewhere that wants to see it.
12: #
13: # Two things it will never do, by design:
14: #   - handle a sudo password. The install step opens a real terminal and lets
15: #     the human type it. Nothing here reads, stores or passes one.
16: #   - create or hold the Sunshine admin login. That is the human's secret.

38: jesc() { printf '%s' "${1-}" | sed -e 's/\\/\\\\/g' -e 's/"/\\"/g' -e 's/\t/ /g' | tr -d '\000-\037'; }
39: jbool() { [[ ${1:-0} == 1 ]] && printf 'true' || printf 'false'; }

43: sunshine_installed() { have sunshine; }
44: sunshine_running()   { pgrep -x sunshine >/dev/null 2>&1; }
45: # pgrep -c prints its count AND exits non-zero when that count is zero, so a
46: # `|| echo 0` fallback appends a second zero and every arithmetic test downstream
47: # blows up on "0\n0". Capture, then default.
48: sunshine_count()     { local n; n=$(pgrep -cx sunshine 2>/dev/null); printf '%s' "${n:-0}"; }
49: 
50: sunshine_version() {
51:   sunshine_installed || return 0
52:   pacman -Q sunshine 2>/dev/null | awk '{print $2}'
53: }

55: # Which unit name this package actually ships, if any. Empty means the package
56: # provides no user unit and the Hyprland autostart line is the only launcher.
57: sunshine_unit() {
58:   local u
59:   for u in "$UNIT_NEW" "$UNIT_OLD"; do
60:     systemctl --user list-unit-files "$u" >/dev/null 2>&1 &&
61:       systemctl --user list-unit-files --no-legend "$u" 2>/dev/null | grep -q . && { printf '%s' "$u"; return; }
62:   done
63: }

65: # A unit that is enabled AND an autostart line means two Sunshines fighting over
66: # one display. Beam reports it rather than silently picking a winner.
67: unit_enabled() {
68:   local u; u=$(sunshine_unit); [[ -n $u ]] || return 1
69:   [[ $(systemctl --user is-enabled "$u" 2>/dev/null) == "enabled" ]]
70: }

72: ufw_rules() {
73:   local n
74:   have ufw || { printf '0'; return; }
75:   n=$(sudo -n ufw status 2>/dev/null | grep -c "$UFW_COMMENT")
76:   printf '%s' "${n:-0}"
77: }

79: autostart_ok() { [[ -f $AUTOSTART ]] && grep -Fxq "$AUTOSTART_ENTRY" "$AUTOSTART"; }

81: admin_up() {
82:   have curl || return 1
83:   curl -sk --max-time 2 -o /dev/null "$ADMIN_URL" 2>/dev/null
84: }

86: # The admin username lives in sunshine.conf; the password is a hash we never
87: # read. Its presence is how we know the human finished the login step.
88: admin_configured() { [[ -f $SUNSHINE_CONF ]] && grep -qE '^username[[:space:]]*=[[:space:]]*\S' "$SUNSHINE_CONF"; }

90: paired_clients() {
91:   local f="$SUNSHINE_DIR/sunshine_state.json"
92:   [[ -f $f ]] || { echo 0; return; }
93:   local n
94:   if have jq; then
95:     n=$(jq -r '[.. | objects | select(has("uniqueid") or has("uniqueID"))] | length' "$f" 2>/dev/null | tail -1)
96:   else
97:     n=$(grep -co 'uniqueid' "$f" 2>/dev/null)
98:   fi
99:   [[ $n =~ ^[0-9]+$ ]] || n=0
100:   printf '%s' "$n"
101: }

103: # What Sunshine itself said it found, rather than what we guess from /dev/dri.
104: # A virtio render node looks like a GPU and cannot encode a single frame, so
105: # the only honest answer comes from Sunshine's own log.
106: encoder() {
107:   [[ -f $SUNSHINE_LOG ]] || return 0
108:   grep -aoiE 'Found H\.?264 encoder: *[a-z0-9_]+' "$SUNSHINE_LOG" 2>/dev/null |
109:     tail -1 | sed -E 's/.*: *//'
110: }

112: encoder_kind() {
113:   local e; e=$(encoder)
114:   case "$e" in
115:     "")            printf 'unknown' ;;
116:     *vaapi*|*nvenc*|*qsv*|*amf*|*vt*) printf 'hardware' ;;
117:     *)             printf 'software' ;;
118:   esac
119: }

121: display_found() {
122:   [[ -f $SUNSHINE_LOG ]] && grep -aqiE 'Found display|Found monitor' "$SUNSHINE_LOG"
123: }

125: # Last CONNECTED/DISCONNECTED wins. Tail only: the log is append-only and a long
126: # one would otherwise cost a full read on every two-second poll.
127: streaming() {
128:   [[ -f $SUNSHINE_LOG ]] || return 1
129:   local last
130:   last=$(grep -aiE 'CLIENT (CONNECTED|DISCONNECTED)' "$SUNSHINE_LOG" 2>/dev/null | tail -1)
131:   [[ $last == *ONNECTED* && $last != *DISCONNECTED* ]]
132: }

135: # iPad is; the LAN address only works at home. Prefer the one that travels.

137:   local ts lan

139:     ts=$(tailscale ip -4 2>/dev/null | head -1)

143: }

146:   local a; a=$(address)

254: # Finish or undo whatever the stock installer left half-done, and make sure
255: # exactly one Sunshine can start.
256: cmd_repair() {
257:   local changed=0
258: 
259:   if ! sunshine_installed; then
260:     echo "Sunshine is not installed yet. Run: omarchy-beam install"
261:     return 1
262:   fi
263: 
264:   # The autostart line is the launcher Omarchy expects; the unit is the one the
265:   # package ships. Keeping both is the double-Sunshine bug.
266:   if unit_enabled; then
267:     echo "Disabling the packaged systemd unit so only one Sunshine starts."
268:     systemctl --user disable --now "$(sunshine_unit)" >/dev/null 2>&1
269:     changed=1
270:   fi
271: 
272:   if ! autostart_ok; then
273:     echo "Adding the Hyprland autostart line."
274:     mkdir -p "$(dirname "$AUTOSTART")"; touch "$AUTOSTART"
275:     printf '\n%s\n' "$AUTOSTART_ENTRY" >>"$AUTOSTART"
276:     changed=1
277:   fi
278: 
279:   if have ufw && [[ $(ufw_rules) -eq 0 ]]; then
280:     echo "Opening Moonlight's ports. You will be asked for your password."
281:     beam_open_ports || echo "Firewall step failed. Run 'omarchy-beam ports' to retry."
282:     changed=1
283:   fi
284: 
285:   if ! sunshine_running; then
286:     echo "Starting Sunshine."
287:     setsid -f uwsm-app -- sunshine >/dev/null 2>&1 </dev/null ||
288:       setsid -f sunshine >/dev/null 2>&1 </dev/null
289:     sleep 2
290:     changed=1
291:   fi
292: 
293:   [[ $changed -eq 0 ]] && echo "Nothing to repair."
294:   return 0
295: }

297: # Reuse the stock installer's own firewall function rather than hand-rolling
298: # rules, so Beam opens exactly what Omarchy opens and nothing wider.
299: beam_open_ports() {
300:   local src=/usr/bin/omarchy-install-service-sunshine n d
301:   [[ -f $src ]] || { echo "Omarchy's sunshine installer is missing."; return 1; }
302:   n=$(grep -nxF 'echo "Installing Sunshine..."' "$src" | cut -d: -f1)
303:   [[ -n $n ]] || { echo "Cannot read the installer's firewall function."; return 1; }
304:   d=$(mktemp -d) || return 1
305:   { head -n $((n - 1)) "$src"; echo open_ufw_ports; } >"$d/ufw.sh"
306:   chmod 0755 "$d"; chmod 0644 "$d"/*.sh
307:   # One root call for the whole step: the script's inner "sudo ufw" lines then
308:   # need no further authentication. Priming sudo and running a subshell does
309:   # not work over SSH without a TTY, which is how this fails silently.
310:   sudo env PATH=/usr/bin bash "$d/ufw.sh"
311:   local rc=$?
312:   rm -rf -- "$d"
313:   return $rc
314: }

338: # A QR code beats typing an IP address on a touch keyboard, and beats searching

341: cmd_qr() {
342:   local text="${1:?usage: omarchy-beam qr <text>}" fg="${2:-000000}" bg="${3:-FFFFFF}"
343:   have qrencode || { echo "qrencode is not installed" >&2; return 1; }

347:   [[ -f $out ]] || qrencode -o "$out" -s 8 -m 2 -l M \
348:     --foreground="$fg" --background="$bg" "$text" 2>/dev/null
349:   printf '%s' "$out"

352: # The single highest-value automation here. A locked or idle session streams a
353: # black screen, which is the first row of every troubleshooting table ever
354: # written about Sunshine. Hold the session awake while an iPad is watching, and
355: # give idling back the moment it stops.
356: cmd_hold() {
357:   local want="${1:-auto}" held="$STATE_DIR/awake-held"
358:   have omarchy || return 0
359:   export OMARCHY_PATH=${OMARCHY_PATH:-/usr/share/omarchy}
360:   [[ $want == auto ]] && { streaming && want=on || want=off; }
361:   case "$want" in
362:     on)
363:       [[ -f $held ]] && return 0
364:       omarchy toggle idle stay-awake >/dev/null 2>&1 && : >"$held"
365:       omarchy system wake >/dev/null 2>&1
366:       ;;
367:     off)
368:       [[ -f $held ]] || return 0
369:       omarchy toggle idle allow-idle >/dev/null 2>&1 && rm -f "$held"
370:       ;;
371:   esac
372: }

6: //
7: // The CLI in bin/omarchy-beam owns every fact and every action. This service

92:     ufwRules = d.ufwRules || 0
93:     ufwPresent = !!d.ufwPresent
94:     autostart = !!d.autostart
95:     adminUp = !!d.adminUp
96:     adminConfigured = !!d.adminConfigured

102:     recommendedBitrate = d.recommendedBitrate || recommendedBitrate
103:     pairedClients = d.pairedClients || 0
104:     streaming = !!d.streaming
105:     locked = !!d.locked

107:     addressKind = d.addressKind || "none"
108:     lanAddress = d.lanAddress || ""
109:     nextStep = d.nextStep || 1

111:     ready = true

114:     // two processes a second for as long as someone is watching a film.
115:     if (holdAwake && wasStreaming !== root.streaming) run(["hold", root.streaming ? "on" : "off"])

119:     id: poll
120:     command: [root.cli, "status"]
121:     stdout: StdioCollector { waitForEnd: true; onStreamFinished: root.apply(text) }
122:   }

125:   // action ran, so a second click during an install simply vanished.

128:   Process {

131:     stderr: StdioCollector { waitForEnd: true; onStreamFinished: root.append(text) }
132:     onRunningChanged: {

134:     }

137:   function append(text) {
138:     if (!text) return
139:     var t = String(text).trim()
140:     if (!t) return
141:     // Keep the tail only: the log box is a fixed height by design and an
142:     // unbounded string here is a slow leak on a long-lived shell.
143:     var lines = (root.log ? root.log + "\n" + t : t).split("\n")
144:     root.log = lines.slice(-200).join("\n")
145:   }
146: 
147:   function drain() {
148:     if (act.running) return
149:     var q = root.pending
150:     if (!q || q.length === 0) return
151:     // Never mutate a QML var array in place: shift() hands back the item but
152:     // leaves the property on the original array, so the queue never empties.
153:     var next = q[0]
154:     root.pending = q.slice(1)
155:     act.command = next
156:     root.busy = true
157:     act.running = true
158:   }
159: 
160:   function run(args) {
161:     var cmd = [root.cli].concat(args)
162:     var q = root.pending.slice(-3)
163:     q.push(cmd)
164:     root.pending = q
165:     drain()
166:   }

===== prototype/QrCode.qml =====
1: import QtQuick
2: import Quickshell
3: import Quickshell.Io
4: 
5: // A QR code the iPad camera can read.
6: //
7: // This exists because the two worst moments in this setup are both typing on a
8: // touch keyboard: finding the right app in a store full of near-namesakes, and
9: // entering an IP address. A camera does both perfectly in a second.
10: //
11: // The PNG is rendered by qrencode through the CLI and cached by content, so
12: // reopening the wizard costs nothing.
13: Item {
14:   id: root
15:   property string text: ""
16:   property string cli: ""
17:   property int size: 160
18: 
19:   property string path: ""
20:   readonly property bool loaded: path !== ""
21: 
22:   implicitWidth: size
23:   implicitHeight: size
24: 
25:   onTextChanged: regen()
26:   onCliChanged: regen()
27:   Component.onCompleted: regen()
28: 
29:   function regen() {
30:     if (!text || !cli) { path = ""; return }
31:     gen.command = [cli, "qr", text]
32:     gen.running = true
33:   }
34: 
35:   Process {
36:     id: gen
37:     stdout: StdioCollector {
38:       waitForEnd: true
39:       onStreamFinished: {
40:         var p = String(text).trim()
41:         root.path = p ? p : ""
42:       }
43:     }
44:   }
45: 
46:   // White quiet zone always, in every theme. A QR on a dark themed background
47:   // with a themed foreground is a QR that phones refuse to read, and the user
48:   // has no way to know why.
49:   Rectangle {
50:     anchors.fill: parent
51:     radius: 6
52:     color: "#ffffff"
53:     border.width: 0
54:     visible: root.loaded
55: 
56:     Image {
57:       anchors.fill: parent
58:       anchors.margins: 4
59:       source: root.loaded ? "file://" + root.path : ""
60:       fillMode: Image.PreserveAspectFit
61:       smooth: false
62:       cache: true
63:     }
64:   }
65: }
